# USER_ROLES.md
## CWS Penyuluh

### 1. Tujuan Dokumen

Dokumen ini menjelaskan struktur pengguna, hak akses, batasan akses, dan tanggung jawab setiap role pada sistem CWS Penyuluh.

Struktur pengguna dibuat sederhana agar mudah dikelola.

Sistem memiliki tiga aktor:

1. Pengunjung
2. Akun BPP
3. Admin CWS Pusat

Dari sisi login, hanya ada dua role:

- BPP
- Admin CWS

Pengunjung tidak memiliki akun.


### 2. Konsep Akun

Sistem tidak menyediakan fitur registrasi mandiri.

Seluruh akun BPP dibuat dan dikelola oleh Admin CWS Pusat.

Penyuluh tidak memiliki akun pribadi.

Penyuluh hanya disimpan sebagai data pegawai yang terhubung dengan BPP.

Contoh:

BPP Garut Kota memiliki tujuh penyuluh.

BPP Garut Kota memiliki satu akun operator.

Operator login menggunakan akun BPP Garut Kota.

Setelah login, operator dapat memilih nama penyuluh yang akan mengirim laporan.

Dengan konsep ini, penyuluh tidak perlu memiliki username dan password masing-masing.

### 4. Pengunjung

#### 4.1 Deskripsi

Pengunjung adalah masyarakat umum yang membuka website CWS Penyuluh tanpa login.

Pengunjung hanya dapat melihat informasi yang ditentukan sebagai informasi publik.


#### 4.2 Login

Pengunjung tidak perlu login.


#### 4.3 Hak Akses

Pengunjung dapat:

- Melihat halaman Beranda.
- Melihat halaman Tentang Kami.
- Melihat profil CWS Penyuluh.
- Melihat alamat dan kontak.
- Melihat struktur organisasi.
- Melihat Keragaan BPP.
- Melihat daftar 42 BPP.
- Melihat detail BPP.
- Melihat daftar penyuluh yang bersifat publik.
- Melihat berita.
- Membuka detail berita.
- Melihat video.
- Membuka video YouTube.
- Membuka video Google Drive.
- Melihat lokasi BPP pada peta.
- Mengakses informasi kontak.


#### 4.4 Batasan Pengunjung

Pengunjung tidak dapat:

- Register.
- Login tanpa akun resmi.
- Mengakses Dashboard BPP.
- Mengakses Dashboard Admin.
- Melihat laporan.
- Mengupload laporan.
- Mengakses file laporan.
- Mengubah data BPP.
- Mengubah data penyuluh.
- Membuat berita.
- Mempublikasikan berita.
- Mengelola video.
- Mengakses informasi internal.


### 5. Admin CWS Pusat

#### 5.1 Deskripsi

Admin CWS Pusat merupakan pengelola utama sistem.

Admin memiliki akses penuh terhadap pengelolaan BPP, penyuluh, akun, laporan, berita, video, dan konten website.


#### 5.2 Login

Admin wajib login.


#### 5.3 Role Database

Role:

admin_cws


### 6. Pengelolaan Akun oleh Admin CWS

Hanya Admin CWS yang dapat membuat akun BPP.

Website tidak menyediakan menu Register.


#### 6.1 Admin CWS Dapat

- Membuat akun BPP.
- Menentukan akun terhubung ke BPP mana.
- Melihat daftar akun BPP.
- Mengubah data akun.
- Mengaktifkan akun.
- Menonaktifkan akun.
- Reset password.
- Mengganti username atau email.
- Melihat status akun.


#### 6.2 Data Akun BPP

Data akun dapat terdiri dari:

- Nama akun.
- Username.
- Email.
- Password.
- BPP.
- Role.
- Status.
- Tanggal dibuat.


Contoh:

Nama akun:
Operator BPP Garut Kota

Username:
bpp_garutkota

Email:
garutkota@cws.id

Role:
bpp

BPP:
BPP Garut Kota

Status:
Aktif


#### 6.3 Aturan Pembuatan Akun

Akun hanya dapat dibuat oleh Admin CWS.

BPP tidak dapat mendaftarkan akun sendiri.

BPP tidak dapat membuat akun operator tambahan sendiri.

Jika BPP membutuhkan akun tambahan, Admin CWS yang membuatnya.


### 7. Jumlah Akun per BPP

Sistem sebaiknya mendukung satu atau lebih akun untuk satu BPP.

Versi awal dapat menggunakan satu akun utama untuk setiap BPP.

Contoh:

BPP Garut Kota

Akun 1:
Operator BPP Garut Kota

Jika nanti dibutuhkan:

Akun 2:
Koordinator BPP Garut Kota

Kedua akun tetap terhubung ke BPP Garut Kota.


### 8. Status Akun

Status akun:

- Aktif
- Nonaktif


Akun aktif dapat login.

Akun nonaktif tidak dapat login.

Data akun nonaktif tidak langsung dihapus agar riwayat aktivitas tetap tersimpan.


### 9. Akun BPP

#### 9.1 Deskripsi

Akun BPP digunakan oleh operator BPP.

Akun tersebut mewakili satu BPP tertentu.

Akun BPP digunakan untuk mengelola proses pengiriman laporan penyuluh dan berita.


#### 9.2 Login

Akun BPP wajib login.


#### 9.3 Role Database

Role:

bpp


#### 9.4 Relasi BPP

Setiap akun BPP wajib memiliki:

bpp_id

Contoh:

user_id:
15

role:
bpp

bpp_id:
5


Sistem menggunakan bpp_id untuk menentukan data yang boleh diakses oleh akun tersebut.


### 10. Dashboard BPP

Setelah login, akun BPP diarahkan ke Dashboard BPP.

Tampilan Dashboard BPP berbeda dari website publik.

Dashboard dapat menampilkan:

- Nama BPP.
- Total penyuluh.
- Jumlah penyuluh sudah mengirim laporan.
- Jumlah penyuluh belum mengirim laporan.
- Laporan menunggu validasi.
- Laporan disetujui.
- Laporan perlu revisi.
- Deadline laporan terdekat.
- Progress pengumpulan.
- Permintaan laporan terbaru.
- Aktivitas terbaru.


### 11. Hak Akses Data BPP

Akun BPP dapat:

- Melihat profil BPP sendiri.
- Melihat alamat.
- Melihat kontak.
- Melihat foto.
- Melihat wilayah kerja.
- Melihat lokasi.
- Melihat jumlah penyuluh.


Untuk versi awal, perubahan data utama BPP dilakukan oleh Admin CWS.

Akun BPP tidak dapat mengubah BPP lain.


### 12. Hak Akses Data Penyuluh

Akun BPP dapat:

- Melihat daftar penyuluh dari BPP sendiri.
- Mencari penyuluh.
- Melihat detail penyuluh.
- Melihat jabatan.
- Melihat status kepegawaian.
- Melihat wilayah binaan.
- Melihat status laporan penyuluh.


Untuk versi awal, data penyuluh utama dikelola oleh Admin CWS.


Akun BPP tidak dapat:

- Menambah penyuluh BPP lain.
- Mengubah penyuluh BPP lain.
- Melihat data internal penyuluh BPP lain.


### 13. Relasi Penyuluh dengan BPP

Setiap penyuluh hanya terhubung dengan satu BPP aktif.

Contoh:

Muhammad Rafi

BPP:
BPP Garut Kota


Jika akun BPP Garut Kota login, Muhammad Rafi muncul pada daftar penyuluh.

Jika akun BPP Cilawu login, Muhammad Rafi tidak boleh muncul.


### 14. Permintaan Laporan

Permintaan laporan dibuat oleh Admin CWS Pusat.

Akun BPP hanya menerima dan mengerjakan permintaan tersebut.


#### 14.1 Admin CWS Dapat

- Membuat permintaan laporan.
- Menentukan nama laporan.
- Menentukan jenis laporan.
- Menentukan periode.
- Menentukan tanggal mulai.
- Menentukan deadline.
- Menentukan format file.
- Menentukan ukuran maksimal file.
- Menambahkan deskripsi.
- Menambahkan keterangan.
- Mengaktifkan permintaan.
- Menutup permintaan.


#### 14.2 Akun BPP Dapat

- Melihat permintaan laporan.
- Melihat periode.
- Melihat deadline.
- Melihat format file.
- Melihat keterangan.
- Membuka detail permintaan.


### 15. Daftar Penyuluh pada Permintaan Laporan

Ketika akun BPP membuka permintaan laporan, sistem menampilkan semua penyuluh pada BPP tersebut.

Contoh:

BPP Garut Kota

Permintaan:
Laporan Bulanan Agustus 2026

Daftar:

Muhammad Rafi
Sudah Mengirim

Ahmad Fauzan
Belum Mengirim

Siti Nurhayati
Perlu Revisi


Sistem harus menampilkan status setiap penyuluh secara jelas.


### 16. Upload Laporan

Akun BPP dapat mengupload laporan atas nama penyuluh dari BPP sendiri.

Alur:

BPP login.

Buka permintaan laporan.

Pilih penyuluh.

Upload file.

Kirim laporan.


### 17. Data Otomatis Saat Upload

Saat akun BPP memilih penyuluh, sistem otomatis menentukan:

- Nama penyuluh.
- BPP.
- Permintaan laporan.
- Jenis laporan.
- Periode.
- Akun pengupload.
- Tanggal upload.
- Versi.
- Status.


Operator tidak perlu memilih BPP secara manual.


### 18. Batasan Upload Laporan

Akun BPP hanya dapat mengupload laporan jika:

penyuluh.bpp_id = user.bpp_id


Contoh:

Akun BPP Garut Kota hanya dapat mengupload laporan untuk penyuluh BPP Garut Kota.


Akun tersebut tidak boleh dapat memanipulasi URL atau request untuk mengupload laporan milik BPP lain.


### 19. Status Laporan

Status utama:

- Belum Mengirim
- Menunggu Validasi
- Disetujui
- Perlu Revisi
- Ditolak


Belum Mengirim berarti penyuluh belum memiliki laporan pada permintaan tersebut.


Menunggu Validasi berarti laporan sudah dikirim dan menunggu pemeriksaan Admin CWS.


Disetujui berarti laporan telah diterima.


Perlu Revisi berarti laporan perlu diperbaiki.


Ditolak berarti laporan tidak diterima.


### 20. Validasi Laporan

Hanya Admin CWS yang dapat melakukan validasi.


Admin dapat:

- Melihat detail laporan.
- Melihat penyuluh.
- Melihat BPP.
- Mengunduh file.
- Melihat tanggal upload.
- Melihat akun pengupload.
- Memberikan catatan.
- Menyetujui laporan.
- Meminta revisi.
- Menolak laporan.


### 21. Catatan Validasi

Jika status menjadi Perlu Revisi, Admin disarankan wajib memberikan catatan.

Contoh:

Perbaiki halaman tanda tangan dan lampiran kegiatan.


Jika laporan ditolak, Admin juga disarankan memberikan alasan.


### 22. Revisi Laporan

Jika laporan berstatus Perlu Revisi, akun BPP dapat mengirim ulang laporan.

Alur:

Admin meminta revisi.

BPP melihat notifikasi.

BPP membuka laporan.

BPP membaca catatan.

BPP upload file baru.

Sistem membuat versi berikutnya.


### 23. Versioning Laporan

Setiap revisi harus menghasilkan versi baru.

Contoh:

Versi 1
Menunggu Validasi

Versi 1
Perlu Revisi

Versi 2
Menunggu Validasi

Versi 2
Disetujui


File versi lama tidak boleh tertimpa.


### 24. Riwayat Laporan BPP

Akun BPP dapat melihat riwayat laporan dari penyuluh pada BPP sendiri.

Informasi dapat mencakup:

- Nama penyuluh.
- Nama laporan.
- Periode.
- Versi.
- Tanggal upload.
- Status.
- Catatan validasi.
- Tanggal validasi.

6

- Progress per BPP.
- Penyuluh sudah mengirim.
- Penyuluh belum mengirim.

- Laporan perlu revisi.
- Laporan disetujui.

6 dari 8
75%

100%

### 43. Pencegahan Manipulasi URL

Sistem tidak boleh hanya mengandalkan URL.

Contoh:

/bpp/reports/25

Jika laporan ID 25 milik BPP lain, sistem harus menolak akses meskipun user mengetahui URL tersebut.


### 44. Keamanan File Laporan

File laporan bersifat internal.

File tidak boleh disimpan dengan URL publik tanpa authorization.

User harus memiliki hak akses sebelum sistem mengizinkan file dibuka atau didownload.


### 45. Reset Password

Jika BPP lupa password:

Operator menghubungi Admin CWS.

Admin CWS membuka menu Akun BPP.

Admin melakukan reset password.

Admin memberikan password baru kepada operator.


Fitur reset mandiri melalui email dapat ditambahkan jika dibutuhkan nanti.


### 46. Logout

Akun BPP dan Admin harus dapat logout.

Setelah logout:

Session dihapus.

User kembali ke halaman login atau website publik.

### 63. Alur Utama Akun BPP

Admin membuat akun.

BPP menerima akun.

BPP login.

BPP masuk dashboard.

BPP melihat permintaan laporan.

BPP melihat penyuluh yang sudah dan belum mengirim.

BPP memilih penyuluh.

BPP upload laporan.

Admin melakukan validasi.

BPP melakukan revisi jika diperlukan.

Laporan selesai dan tersimpan sebagai arsip.


### 64. Kesimpulan

Struktur role CWS Penyuluh dibuat sederhana agar mudah digunakan dan dikelola.

Pengunjung hanya menggunakan website publik.

Penyuluh tidak memiliki akun individual.

Setiap proses pelaporan dilakukan melalui akun BPP.

Seluruh akun BPP dibuat dan dikontrol oleh Admin CWS Pusat.

Akun BPP hanya dapat mengakses penyuluh dan laporan pada BPP masing-masing.

Admin CWS mengelola data utama, akun, permintaan laporan, validasi, berita, video, dan konten website.

Struktur ini sesuai dengan tujuan utama sistem, yaitu menggantikan proses pengumpulan laporan melalui Google Form dan Spreadsheet menjadi sistem terpusat yang lebih mudah dipantau.
